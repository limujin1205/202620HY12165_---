## 💬 주요 논의

### 1. 문제 인식

- 입주 신청자는 사업계획서, 배출시설 명세 같은 서식과 건축물대장을 대부분 읽지 못함
- 배출시설 기준은 지자체 환경과 고시에 있고 지역마다 다름
- 건축물대장 역시 읽을 줄 아는 신청자가 거의 없어, 서류 해석 자체가 진입 장벽이 된다는 점이 출발점으로 지적됨
- 이미 정해진 절차를 사람 대신 AI가 더 빠르게 찾아주는 구조이므로, 정해진 규칙 안에서는 구현이 가능하다는 의견

### 2. 범위 한정

- 전국은 불필요. 서울 공공데이터의 지식산업센터 현황(CSV, 2026년 2월 기준, 약 400개) 활용
- @apricity57-del: 서울 국가산단 '울타리' 지역으로 좁히면 약 200개. 단, 현황 파일에 울타리 구분이 없어 주소로 판별해야 함
- 대안으로 @apricity57-del이 담당했던 인천 부평도 거론
- 지역이 바뀌어도 로직은 같고 기준 데이터만 다르므로, 테스트는 다른 지역으로 해도 무방
- 동대문 패션비즈센터(한국산업단지공단)가 후보로 나왔으나, 서울시 이관 예정이라 @apricity57-del이 제외 의견

### 3. 서비스 흐름 (@LEEEOJ 구상)

1. 사이트 접속 후 입주 가능 여부 테스트 — 업체명, 사업자번호, 업종코드 등 입력
2. 조건 충족 시 '입주 가능' 판정, 신청서 작성으로 이동
3. 추가 정보를 입력받아 신청서 완성

- 진행 순서는 팀 메신저 정리본 기준 **3→1→2→4**가 맞다는 의견(@circlerm). 센터를 먼저 정해야 적합성 판단이 되기 때문이며, 4번은 있으면 좋은 수준으로 봄
- 1차 프로토타입은 **3→1→2까지 틀만** 잡고 4번은 제외

### 4. 서비스 초점과 타겟

- **초점**: 사업계획서·입주계약신청서를 쉽게 쓰도록 돕는 것. 사업 내용 입력 → 업종코드 검색 → 양식 채우기
- 서식에 있는 작성 요령을 AI에 넣어 활용. 공장배치도는 사진 업로드로 처리
- **타겟**: 사업계획서를 쓰는 사장님, 이를 대행하는 행정사, 지자체 담당자
- 지식산업센터는 보통 중개사를 끼므로 중개사도 가능성 있음

### 5. 구현 방식

- 앱이 아닌 웹, @circlerm이 Claude 바이브 코딩으로 기반 제작
- @circlerm은 최근 Claude 바이브 코딩을 조금씩 진행 중이며 결과가 좋다고 평가
- 오픈 API는 불필요, CSV로 충분. Claude API 토큰은 @circlerm이 보유
- 기능별로 나눠 만들면 합치기 어렵다는 우려(@circlerm) → 한 명이 틀을 잡고 나머지가 자료를 대는 방식
- 실패해도 과정은 GitHub에 남아 평가에 도움됨

### 6. 참고 자료와 우려

- @apricity57-del 회사 블로그에 입주 신청 안내가 정리돼 있음. 공개 블로그라 AI 학습 자료로 쓰기로 함 (회사망에서는 접속 안 됨)
- 같은 건물이라도 층·호실마다 용도가 다름(1층 편의점, 2층 공장). 주소 기반으로 판정하려면 건축물대장을 다 넣어야 함
- @apricity57-del은 설명 범위를 가늠하기 어렵다고 함 → 아는 내용을 팀 메신저에 전부 올리고, 그 내용은 AI로 정리하기로 함

## ✅ 결정 사항

1. 빠르게 간단히 구현해 보고, 괜찮으면 구체화하고 아니면 주제를 다시 고른다.
2. 플랫폼은 웹, Claude 바이브 코딩으로 만든다.
3. 서울 센터 1곳으로 프로토타입을 만든 뒤 데이터를 늘린다.
4. 1차는 흐름 3→1→2까지 틀만 잡는다. 4번은 뺀다.
5. 서비스 초점은 사업계획서·입주계약신청서 작성 지원에 둔다.

> 4명이 같은 그림을 그리고 있는지 확인하는 것이 목표이므로, 3번까지 틀을 잡은 뒤 함께 검토한다.
