## 4. 회의 후 검토 (작성자 정리)

> 회의에서 나온 발언을 바탕으로, 결정된 방향을 과제 조건(**생성형 AI 응용 · 오픈소스 공개 · 동종업계 확산**)에 비춰 추가 검토. 다음 논의 자료.

### 4-1. 회의에서 드러난 강점
- **실제 현업의 불만에서 출발:** "유료 서비스인데도 최신화가 안 돼 있다", "기사를 다 볼 수 없어 결국 남의 보고서를 다시 갖다 쓴다" — 두 팀원이 각자 실무에서 겪은 같은 문제
- **공개 데이터로 시연 가능:** 표준산업분류 코드는 공개 자료이고, 상장·외감 기업 재무제표는 전자공시로 공개되어 있다. 3-1에서 지적된 **"모든 걸 가상으로 만들어야 하는"** 문제를 피할 수 있다
- **현업 검증자 존재:** "잘 정리됐다고 판단할 수 있는 사람이 있어야 된다"는 조건을 금융 심사 실무자(@LEEEOJ)와 산업 동향 분석 경험자(@apricity57-del)가 충족
- **확산 대상이 넓다:** "기업 사업체를 평가하는 데들은 다 쓸 것" — 금융기관, 소상공인 지원 기관, 투자자

### 4-2. 차별화 후보 ("한 스푼")
"그냥 크롤링", "클로드로 기사 찾기"와 달라야 한다.
1. **고정된 분석 틀:** 업종마다 같은 항목(조달·판매 구조, 외상 기간, 마진 구조, 주요 리스크)으로 정리 → 업종 간 비교 가능
2. **모든 문장에 출처:** 기사·보고서 출처를 붙이고, 출처 없는 내용은 "추정"으로 표시
3. **숫자는 코드가, 문장은 AI가:** 업종 평균 재무비율은 코드로 계산하고, AI는 결과를 해석하는 문장만 작성 → 숫자 환각 방지
4. **"이 업종은 이걸 주의하세요":** @LEEEOJ가 말한 실무 사용 방식 그대로, 동향 나열이 아니라 **주의 포인트 메모**로 출력

### 4-3. 위험
- **AI가 업종 특성을 그럴듯하게 지어낼 위험** → 출처 강제, 추정 표시
- **기사 수집의 저작권·이용약관 문제** → 공식 API, RSS, 공공기관 보고서 우선
- **비상장 소규모 기업은 재무제표가 공개되지 않음** → 사용자가 직접 입력하는 방식 병행 검토
- **분석 결과를 투자·대출 판단 근거로 오해할 위험** → "참고용" 명시, 최종 판단은 사람

### 4-4. 미결 질문
- 1부의 💬 **"AI가 판단한 동향 분석이나 의견이 어떻게 쓰여요?"**
  - 2부에서 "이 업종은 이러니 이걸 주의하세요, 포인트를 집어주는 정도"라는 **부분 답변**이 나옴
  - 남은 질문: 그 포인트가 **심사 의견서의 한 항목**으로 들어가는지, **심사 전 사전 조사용**인지 → 이 답에 따라 산출물 형태가 정해진다
